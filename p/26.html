Reproject to Web Mercator

Medium Projection ST_TransformEPSG

Solve this in your browser →

Web maps (Google, OSM) draw in Web Mercator (EPSG:3857), but GPS data arrives in WGS84 (EPSG:4326). Reproject three NYC landmarks so they can be plotted on a web map.

Goal

Return name, merc_x, merc_y — the Web Mercator coordinates rounded to whole metres — ordered by name.

⚠️ The classic gotcha: DuckDB's ST_Transform follows the official EPSG:4326 axis order, which is latitude first. Build your input point as ST_Point(lat, lon) — not the usual (lon, lat) — or your landmarks will land in the Indian Ocean.

Expected Output

name               merc_x    merc_y
-----------------  --------  -------
Brooklyn Bridge    -8237297  4969088
Empire State       -8236050  4975301
Statue of Liberty  -8242596  4966606

Table: landmarks

ColumnTypeDescription
nameVARCHARLandmark name
latDOUBLELatitude (WGS84)
lonDOUBLELongitude (WGS84)

ST_Transform(geom, 'EPSG:4326', 'EPSG:3857') reprojects. Sanity check: all of NYC should come out near x ≈ −8.24 million, y ≈ +4.97 million metres.

Hints

💡 Hint 1 Build the point latitude-first: ST_Point(lat, lon). EPSG:4326's official axis order surprises everyone once.
💡 Hint 2 Extract with ST_X/ST_Y after transforming, then ROUND(...) to whole metres.
💡 Hint 3 If your x comes out around +4.5 million, you've got the axis order backwards.
